Codex skills location: where to put SKILL.md

Codex reads skills from the neutral .agents/skills folder, not a Codex-branded one. Here are all the places it looks, in order, how to add a skill, and how to switch one off without deleting it.

Where does Codex look for skills?

OpenAI’s docs list repository, user, admin, and system locations. For a repository, Codex scans .agents/skills in every folder from where you start Codex up to the repo root.

ScopeLocationGood for
Repo$CWD/.agents/skillsSkills for the folder you’re working in, such as one service
Repo$CWD/../.agents/skillsSkills for a shared area in a parent folder
Repo$REPO_ROOT/.agents/skillsSkills for everyone working in the repo
User$HOME/.agents/skillsYour own skills, in any repo
Admin/etc/codex/skillsDefaults for every user on a machine or container
SystemBundled with CodexBuilt-ins such as skill-creator and skill-installer

Two details from the docs: if two skills share a name, Codex doesn’t merge them, and both can appear in skill selectors. And Codex follows symlinked skill folders, so you can keep one copy of a skill and link it into several places.

Because Codex uses the neutral folder, a skill you put in .agents/skills/ can also be read by Cursor, GitHub Copilot, Gemini CLI, and other tools that scan it. Claude Code is the notable exception. It reads .claude/skills/. See which AI bots read SKILL.md.

Add a skill in five steps

  1. Pick the scope. For one repository, use .agents/skills/ at the repo root or in a subfolder. For every repo you work in, use $HOME/.agents/skills/.
  2. Make the skill folder. Create a folder named after the skill, for example .agents/skills/release-notes/.
  3. Save SKILL.md inside it. The file must include name and description. Write the description so it says exactly when the skill should and shouldn’t trigger.
  4. Check that Codex sees it. Codex detects skill changes automatically. Run /skills in the CLI or IDE extension. If the skill doesn’t appear, restart Codex.
  5. Use it. Type $ to mention the skill by name, or describe the task and let Codex pick it.
mkdir -p ~/.agents/skills/release-notes
cat > ~/.agents/skills/release-notes/SKILL.md <<'EOF'
---
name: release-notes
description: Write release notes from merged changes since the last tag. Use when asked for release notes or a changelog. Not for commit messages.
---
1. List merged changes since the last tag.
2. Group them as Added, Changed, Fixed.
3. Show me the draft. Don't publish or tag anything.
EOF

Or let Codex write it: run $skill-creator, which asks what the skill does, when it should trigger, and whether it should stay instruction-only. Instruction-only is the default.

How to use a skill in Codex

  • Explicitly: run /skills, or type $ to mention a skill in your prompt.
  • Implicitly: Codex can choose a skill when your task matches its description.

To stop Codex from picking a skill on its own, the docs describe an optional agents/openai.yaml inside the skill folder with allow_implicit_invocation: false under policy. Explicit $skill mentions still work.

Installing curated and outside skills

Codex ships a $skill-installer skill. The docs’ example installs a curated skill with $skill-installer linear, and you can prompt it to download skills from other repositories. Codex picks up new skills automatically; restart it if one doesn’t appear.

Before you install from someone else’s repo, read the skill and its scripts. Skills in Codex can run code on your machine. My skill safety check lists what to look for. For sharing your own skills widely, OpenAI recommends packaging them as plugins.

Turning a skill off

To disable a skill without deleting it, add an entry to ~/.codex/config.toml:

[[skills.config]]
path = "/path/to/skill/SKILL.md"
enabled = false

Use one selector per entry: an absolute path for one file, or a name to match every skill with that name. If several entries match, the last one wins. Restart Codex after changing the file.

How many skills is too many?

Codex shows the model a list of skills at the start, with each name, description, and file path. Per the docs, that list uses at most 2% of the model’s context window by default, or 8,000 characters when the window size is unknown. With many skills installed, Codex shortens descriptions first, and may leave some skills out with a warning. You can change the budget with skills.max_context_tokens, up to 10,000 tokens.

The practical lesson: keep descriptions short and front-load the trigger words, so a skill still matches when its description gets trimmed.

Codex skills vs ChatGPT skills

OpenAI uses one skills format for both products, and the same skill can work in each. The difference is where it lives. Codex reads skill folders from your machine and repos, as listed above. ChatGPT keeps skills in the Skills tab under Plugins, where you create or upload them. Standalone skills work in the ChatGPT desktop app, Codex CLI, and the IDE extension; skills bundled in plugins also reach ChatGPT on the web and phone. My guide to adding a skill in ChatGPT covers that side.

Troubleshooting

  • The skill isn’t listed. Check the path ends in .agents/skills/<name>/SKILL.md, then restart Codex.
  • You put it in .codex/skills. OpenAI’s current docs list .agents/skills for repo and user skills. Move it there.
  • It never triggers. Mention it with $, or rewrite the description with clearer trigger words.
  • The wrong skill triggers. Two skills may share a name or overlap. Rename one, or disable it in config.toml.

FAQ

Where does Codex look for skills?

In .agents/skills in every folder from your working folder up to the repo root, in $HOME/.agents/skills, in /etc/codex/skills, and in skills bundled with Codex.

How do I use a skill in Codex?

Run /skills or type $ to mention a skill by name. Codex can also pick a skill on its own when your task matches the description.

How do I disable a Codex skill?

Add a [[skills.config]] entry with the skill’s path or name and enabled = false to ~/.codex/config.toml, then restart Codex.

Do Codex skills work in other tools?

Often. Codex uses the neutral .agents/skills folder and the open skills format, which Cursor, GitHub Copilot, Gemini CLI, and others also read. Claude Code reads .claude/skills instead.
