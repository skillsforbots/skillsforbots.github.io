Cursor skills folder: where skills go and how to add one

Cursor loads skills from four folders of its own, plus the Claude and Codex folders for compatibility. Here’s which one to use, how to add a skill in a couple of minutes, and the frontmatter fields Cursor adds.

Where does Cursor look for skills?

Per Cursor’s docs, skills load automatically from these folders:

FolderScope
.agents/skills/This project
.cursor/skills/This project
~/.agents/skills/All projects on this machine
~/.cursor/skills/All projects on this machine
.claude/skills/, .codex/skills/, and the same under ~/Loaded for compatibility with Claude and Codex

Which should you use? If you also use other agents, .agents/skills/ is the widest choice. A survey of vendor docs found that 8 of 11 tools with documented SKILL.md support read that neutral folder. If you want a personal skill available in Cloud Agents, use ~/.cursor/skills/, because that’s the only one that syncs (more below).

Cursor walks skill folders recursively, so you can group skills in category folders. A skill’s identity comes from the folder that holds SKILL.md, not the category. It also finds .cursor/skills/ folders inside subfolders of a repo and scopes those skills to files in that subfolder.

Add a skill in five steps

  1. Pick project or personal. Use .cursor/skills/ or .agents/skills/ in a repo to share the skill with that project, or ~/.cursor/skills/ for every project on your machine.
  2. Make a folder named after the skill. The folder name must match the name in the skill’s frontmatter, in lowercase with hyphens.
  3. Save the SKILL.md inside it. Check the frontmatter has a name and a description. Without a description, the agent is unlikely to pick the skill on its own.
  4. Check that Cursor found it. Open Customize in the sidebar and go to Skills. The skill should be listed.
  5. Use it. Type / in Agent chat and search for the skill, or ask for the job and let the agent choose it.
mkdir -p .agents/skills/reminder-basics
cp SKILL.md .agents/skills/reminder-basics/SKILL.md

How to use a skill in Cursor

  • Automatically: when Cursor starts, it shows the agent the available skills, and the agent decides when one is relevant.
  • By name: type / in Agent chat and search. A skill invoked this way attaches to one message.
  • For a whole session: use the skill as a Custom Mode with Option+Enter on Mac or Alt+Enter on Windows, per the docs.

Cursor also ships built-in skills, including /create-skill to write a new skill and /migrate-to-skills to turn eligible rules and slash commands into skills.

Frontmatter fields Cursor adds

FieldWhat it does
nameRequired. Lowercase letters, numbers, and hyphens, matching the folder name
descriptionRequired. What the skill does and when to use it
pathsGlob patterns. The skill shows up only when the agent works with matching files
disable-model-invocationWhen true, the skill runs only when you type /skill-name
icon, colorThe badge shown when the skill is used as a Custom Mode
metadataAny extra key-value data

Only name and description are part of the portable core. If you share a skill with people on other tools, the Cursor-only fields may be ignored there. My SKILL.md template sticks to the portable fields.

Personal skills and Cloud Agents

Skills in ~/.cursor/skills/ stay on your machine until you sync them. To use them in Cloud Agents, open Settings, Agents, and under Context and Tools turn on Sync Skills for Cloud Agents. The docs note a few limits:

  • Only ~/.cursor/skills/ syncs. Project skills and ~/.agents/skills/ stay local.
  • Synced skills stay private to you, and load in Cloud Agents you start yourself.
  • Automation runs don’t load synced skills. To give an automation a skill, put it in the repo’s .cursor/skills/ folder.

Installing skills from a GitHub repo

Cursor doesn’t import skills from a repo on its own. Its docs say to package them in a plugin and publish it through a marketplace: import the repo in Customize with From GitHub Repository (the repo needs a .cursor-plugin/marketplace.json), or add it as a team marketplace, then install the plugin.

For a single skill from someone else’s repo, copying the folder into .agents/skills/ is simpler. Read it first. My skill safety check covers what to look for, and the SKILL.md checker flags risky wording.

Sharing one skill across Cursor and other tools

If you use Cursor alongside Claude Code or Codex, keep each skill in one place. The simplest setup is a single .agents/skills/ folder in the repo, which Cursor and Codex both read, plus a symlink from .claude/skills/ for Claude Code. Stick to name, description, and plain instructions in the shared copy, and keep tool-specific fields like paths or Custom Mode badges to skills only Cursor uses. Add an “ask before acting” section to any skill that can push code, post, or deploy. My approval rules template has wording you can paste.

When a skill doesn’t show up

  • Name mismatch. The name must match the folder name.
  • Broken frontmatter. In Cloud Agents, a skill whose frontmatter doesn’t parse or has no description shows a warning naming the skill.
  • Wrong folder for the context. A personal skill in ~/.agents/skills/ won’t reach Cloud Agents. Move it to ~/.cursor/skills/ and sync.
  • Scoped by paths or a nested folder. The skill only appears when you work on matching files.
  • It never triggers. Sharpen the description, or invoke it with /.

FAQ

Where is the Cursor skills folder?

Cursor loads skills from .agents/skills/ and .cursor/skills/ in a project, and from ~/.agents/skills/ and ~/.cursor/skills/ for all projects. It also reads the Claude and Codex skill folders for compatibility.

How do I run a skill in Cursor?

Type / in Agent chat and search for the skill name, or ask for the job and let the agent pick the skill from its description.

Do Cursor skills work in Cloud Agents?

Personal skills in ~/.cursor/skills/ do once you turn on Sync Skills for Cloud Agents under Settings, Agents. For automations, put the skill in the repo’s .cursor/skills/ folder.

Can I use a Claude Code skill in Cursor?

Yes. Cursor reads .claude/skills/ and ~/.claude/skills/ for compatibility. Claude-only frontmatter fields may not do anything in Cursor.
