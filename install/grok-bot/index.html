How to install Grok Bot skills from GitHub (3 ways)

Most Grok Bot skills on GitHub are a folder with one SKILL.md file. Here are the three ways I’ve seen to get one into your bot, which one I use, and how to confirm the bot actually picked it up.

The short answer

Open the skill on GitHub, read it, then paste the SKILL.md into a one-to-one chat with your Grok Bot and ask it to save the text as a private skill with the same name. That works for any skill, from any repo, and you see every word the bot saves. For repos with many skills, giving the bot the repo link is faster. Copying folders by hand is the third option, for people comfortable with the bot’s computer.

What a Grok Bot skill is

The Grok Bot docs describe a skill as a reusable set of instructions for how to do a task: steps, decision rules, expected output, and safety boundaries. A routine is the other building block. It tells one bot when to run a workflow. The docs suggest you get a task working once, save the method as a skill, and only then automate it.

Two details from the docs matter for installing:

  • Private skills are one library shared by all your bots. Install a skill once and every bot on your account can use it, although a bot may still need the right app or login for the work.
  • You use a skill by asking for it by name. You can also use @ to point at bots, groups, routines, and apps.

On GitHub, almost every Grok Bot skill repo uses the open Agent Skills layout: one folder per skill, and inside it a SKILL.md with a name and description at the top and plain instructions below. If you want the format explained line by line, see my annotated SKILL.md template.

Install a skill in five steps

  1. Pick the skill and read it first. Open the skill’s SKILL.md on GitHub and read the whole file. Check what it tells the bot to do, what it may send or spend, and whether it ships scripts. My safety check guide has a five-minute version of that review.
  2. Fill in the placeholders. If the file has [BRACKET] placeholders, replace them before the bot saves it. Leave nothing in brackets, or the bot may guess.
  3. Install it one of three ways. Paste the file and ask the bot to save it as a private skill, give the bot the repo link and ask it to install the skill, or have the bot copy the folder into its skill library with the repo’s own install steps. Each method is explained below.
  4. Check that the bot can see it. Ask the bot which private skills it can use. If the new one is missing, open Connect apps in the sidebar, select the connected count next to the title, and turn the skill on for that bot under Private skills.
  5. Test it on something low-stakes. Ask for the skill by name with a harmless request, and watch for the rules you expect, such as a draft and a pause before anything is sent.

Way 1: paste the SKILL.md and ask the bot to save it

This is the method I use, and the one my own pack pages describe.

  1. On GitHub, open the skill folder and click SKILL.md. Use the copy button on the file view, or open the Raw view and copy everything.
  2. Replace any placeholders, such as an approval channel or a reminder time.
  3. In a one-to-one chat with your bot, paste the text with a short request:
Save the text below as a private skill named reminder-basics.
Keep the name and description exactly as written.
Then tell me the skill's name and one-line description.

[paste the full SKILL.md here]

Why I like it: nothing is fetched from the internet by the bot, so a changed file or a lookalike repo can’t slip in. You also read every line before it’s saved. The catch: skills that ship scripts or reference files need those files too, so this works best for instruction-only skills, which is what most everyday skills are.

Way 2: give the bot the repo link

Several community repos document a one-line install message. The wording differs, but the idea is the same: point the bot at the folder and ask it to install the skill into your private skill library.

Install this skill into my private skill library:
https://github.com/skillsforbots/grok-bot-skills/tree/main/skills/reminder-basics
Before saving, show me the skill's name, description,
and any scripts it includes, and wait for my OK.

The last two lines are my addition. They make the bot show you what it fetched before it saves anything. Repos such as d-gangz/grokbot-skills and ofershap/grok-bot-skills print their own install prompt in the README, and bostonaholic/grokbot-skills tells the bot to follow the repo’s AGENTS.md. Use the repo’s own wording when it has one. Note that this method is described by repo authors, not on the docs.x.ai skills page, so treat it as a convenience and check the result.

Content the bot reads on a web page is information, not an order from you. A well-behaved bot should follow your request, not instructions buried in a README. That’s one more reason to ask it to show you the skill before it saves.

Way 3: copy the folder into the skill library

Grok Bot works on its own cloud computer, and community notes and repos say private skills live there as folders. One repo’s install script, for example, copies each skills/<name>/ folder into a workflows folder under the bot’s agent-data directory. docs.x.ai doesn’t document that folder, so I treat the exact path as unofficial and liable to change.

If a repo ships a script for this, read the script before you let the bot run it. A copy script should only copy files. If it downloads other code, asks for keys, or touches anything outside the skills folder, stop.

Use this method when a skill includes scripts/, references/, or assets/ folders that the paste method would leave behind, or when you want updates with a git pull.

How do I know the skill loaded?

Ask two questions in a new chat:

Which private skills can you use right now?
If I asked you to use reminder-basics, what would you do first?

The bot should list the skill and describe its first step in its own words. If it can’t find the skill, the docs say to open Connect apps in the sidebar, select the connected count next to the title, and enable the skill for that bot under Private skills. Then run one real, low-stakes request and check the output against the skill’s rules.

Free tip: test the approval rules on purpose

If the skill says “ask before sending,” ask the bot to send a short message to yourself. It should show you a draft and wait. Grok Bot also has its own Auto Review approval cards and Ask first rules in Settings. Keep those on. A skill is a second layer, not a replacement.

What goes wrong, and fixes

  • The bot saved a different name. Ask it to rename the skill to match the name line. Matching names make the skill easier to ask for.
  • Placeholders were left in. Ask the bot to show the saved skill, then give it the filled-in values and ask it to update the skill.
  • The skill never triggers. Ask for it by name. If it still doesn’t run, the description may be too vague. My SKILL.md checker flags short or vague descriptions.
  • It works in one bot but not another. Check that the skill is enabled for that bot under Private skills.
  • You want it to run on a schedule. That’s a routine, not a skill. See skills vs routines.

FAQ

Can Grok Bot install a skill straight from a GitHub link?

Several community repos document that you can send the bot a repo or folder link and ask it to install the skill into your private skill library. The docs.x.ai skills page doesn’t describe that method, so ask the bot to show you the skill’s name, description, and any scripts before it saves.

Do I have to install a skill on every bot?

No. The Grok Bot docs say private skills are one library shared by all your bots. If one bot can’t see a skill, enable it for that bot under Private skills in Connect apps.

Is pasting a SKILL.md safe?

It’s the method where you see the most, because you read every line before the bot saves it. A skill is still instructions a bot follows, so read it first, keep your approval settings on, and test it on something low-stakes.
