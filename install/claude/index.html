How to add a skill to Claude and Claude Code

Claude reads skills in two different places that don’t sync: the Claude apps, where you upload a ZIP, and Claude Code, which reads folders on your computer. Here are the steps for each, checked against Anthropic’s docs.

Which Claude are you using?

Anthropic documents skills on three surfaces: the Claude apps (claude.ai, desktop, and mobile), Claude Code, and the Claude API. A third-party survey of vendor docs notes an important detail from Anthropic’s overview: custom skills don’t sync across surfaces. A skill you upload on claude.ai won’t appear in Claude Code on your laptop, and the reverse is also true.

Per Anthropic’s help center, skills are available on Free, Pro, Max, Ultra, Team, and Enterprise plans, and they need code execution turned on. Anthropic also ships built-in skills for Word, Excel, PowerPoint, and PDF files that Claude uses on its own when relevant.

Add a skill in the Claude apps

  1. Turn on code execution. On claude.ai, go to Settings, Capabilities, and make sure code execution and file creation is on. In the updated layout it’s called Create and edit files. On Team and Enterprise plans, an owner enables skills in Organization settings first.
  2. Zip the skill folder. Put the folder that holds SKILL.md into a ZIP file. The folder name should match the skill’s name.
  3. Upload it. Go to Customize, Skills. Click the + button, then Create skill, then Upload a skill, and choose the ZIP.
  4. Turn it on. The skill appears in your list with a toggle. Make sure it’s on.
  5. Test it. Start a new chat and make a request that matches the skill’s description. Try a few phrasings.

Uploaded skills are private until you share them. On Team and Enterprise plans you can share a skill with people or groups if your organization allows it.

If the upload fails, the help center lists the usual causes: the folder name doesn’t match the skill name, the SKILL.md file is missing, or the name or description has invalid characters. My free SKILL.md checker catches the name and description problems before you upload.

Add a skill in Claude Code

Claude Code reads skills from folders. Its docs say Claude Code skills follow the Agent Skills open standard, with extra Claude Code features such as invocation control and running in a subagent.

  1. Make a folder for the skill in your personal skills folder, for example ~/.claude/skills/reminder-basics/.
  2. Save the skill as SKILL.md inside it.
  3. Start Claude Code with claude. It picks up changes to skill files on its own.
  4. Ask “What skills are available?” and check the new skill is listed.
  5. Use it by asking for something that matches its description, or type /reminder-basics to run it directly.
mkdir -p ~/.claude/skills/reminder-basics
cp SKILL.md ~/.claude/skills/reminder-basics/SKILL.md

Claude Code skill folders

WherePathWho gets it
Personal~/.claude/skills/<name>/SKILL.mdAll your projects on this machine, but not Cowork or cloud sessions
Project.claude/skills/<name>/SKILL.mdSessions in that repository. Commit it to share with your team
Nested<subfolder>/.claude/skills/<name>/SKILL.mdLoads when Claude works on files in that folder
Plugin<plugin>/skills/<name>/SKILL.mdWherever the plugin is on, as /plugin-name:skill-name
EnterpriseThe managed settings folderEveryone on machines where your organization deploys it

When two locations have a skill with the same name, the docs say enterprise beats personal, and personal beats project. Two quirks: don’t name a skill folder synced, which Claude Code uses for skills downloaded from claude.ai, and note that Claude Code lists only its own .claude/skills folders, not the neutral .agents/skills folder that many other tools read.

If you use several tools, keep one copy of each skill and symlink it. The docs say a skill folder can be a symlink, and Claude Code loads it once even if several locations point to it.

Cowork and cloud sessions

Cowork sessions and cloud sessions, including cloud scheduled tasks, don’t read ~/.claude/skills/ on your computer. Per the Claude Code docs, both load the skills enabled for your claude.ai account, synced at session start. So if a skill should run in a scheduled cloud task, upload it to your claude.ai account too. For more on pairing skills with schedules, see skills vs scheduled tasks.

When a skill won’t trigger

Claude Code’s troubleshooting list, in short:

  1. Check that the description uses words people would naturally say.
  2. Check that the skill shows up when you ask “What skills are available?”
  3. Rephrase your request to match the description more closely.
  4. Invoke it directly with /skill-name.
  5. If the YAML header is broken, Claude Code still loads the body but can’t match your description. Run with --debug to see the parse error.

In the Claude apps, check the toggle is on, start a fresh chat, and test a few phrasings, as Anthropic suggests. Most “it never triggers” problems come down to a vague description. The description is what Claude matches on, so say what the skill does and when to use it, in plain words.

FAQ

Where do Claude Code skills go?

Personal skills go in ~/.claude/skills/<name>/SKILL.md and work in all your projects on that machine. Project skills go in .claude/skills/<name>/SKILL.md inside the repository.

How do I upload a skill to claude.ai?

Zip the skill folder, then go to Customize, Skills, click +, choose Create skill, then Upload a skill. Code execution must be on in Settings, Capabilities.

Do my Claude Code skills show up on claude.ai?

No. Custom skills don’t sync across Claude surfaces. Upload the skill to claude.ai separately if you want it there, in Cowork, or in cloud scheduled tasks.

Can I use a skill made for another tool in Claude?

Often, yes. Claude Code follows the Agent Skills standard, so a SKILL.md with a name, a description, and plain instructions usually works. Put it in a .claude/skills folder, since Claude Code doesn’t list the neutral .agents/skills folder.
