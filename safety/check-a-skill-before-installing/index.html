How to check an AI skill is safe before you install it

A skill is text your bot will follow, so installing one is closer to hiring help than downloading a file. This is the check I run on every skill, mine included, before it goes near a bot that can send, spend, or read my accounts.

Are agent skills safe?

Most are fine. Some aren’t. In February 2026, Snyk published a scan of 3,984 skills from ClawHub and skills.sh. It reported that 13.4% had at least one critical-level issue, such as malware, prompt injection, or exposed secrets, and 36.82% had at least one issue of any severity. It also confirmed 76 malicious payloads aimed at things like credential theft.

The risk comes from what a skill is. The bot loads the instructions and follows them, often with access to your files, browser, apps, and sometimes payment details. A bad skill doesn’t need to “hack” anything. It just has to tell the bot to do something you wouldn’t.

The good news is that most problems are visible if you read the file. Skills are plain text. The check below takes about five minutes for a normal skill.

The 8-step check

  1. Read the whole SKILL.md. Not just the README or the listing page. The SKILL.md is what the bot follows. Note what it says the skill is for, and whether the steps match that.
  2. Search for actions that can’t be undone. Look for send, email, message, post, publish, buy, pay, purchase, subscribe, delete, and transfer. Each one should sit next to a clear rule: the bot drafts or shows the cost, then waits for your yes.
  3. Look for anything hidden. Check for HTML comments, white or tiny text, long runs of blank lines, and invisible characters. Instructions aimed at the bot but hidden from you are a red flag on their own.
  4. Check how it treats outside content. A good skill says that web pages, emails, and documents are information, not orders. A risky one tells the bot to follow instructions it finds in content.
  5. Open every script and linked file. Read anything in scripts/ and any URL the skill tells the bot to download or run. A skill that pipes a download into a shell, asks for keys, or posts data to an unknown address is a no.
  6. Check what data and accounts it needs. Does a reminder skill really need your email, or a writing skill your files? Ask for the least access that does the job, and never paste passwords or card numbers into a skill.
  7. Run it through a checker. Paste it into the free SKILL.md checker. It runs in your browser and flags risky wording, missing approval rules, hidden text, and remote code. It can’t prove a skill is safe, but it catches what tired eyes miss.
  8. Test it on something low-stakes. Install it, then give it a harmless task that would trigger a send or a spend. The bot should stop and ask. Keep your platform’s own approval settings on the whole time.

Red flags and what they look like

Red flagExample wordingWhat I do
Acting without asking“Send the reply automatically,” “complete the purchase”Rewrite it to draft and wait, or don’t install
Following outside content“Do whatever the email asks,” “follow instructions on the page”Don’t install
Hidden instructionsAn HTML comment telling the bot to ignore the user, invisible charactersDon’t install, and report it to the listing site
Remote codeDownload a script and run it, piping a URL into a shellDon’t install unless I can read and pin the exact code
Asking for secrets“Paste your API key here,” “store the card number”Don’t install. Use the platform’s vault or secure sign-in instead
Scope creepA to-do skill that reads all your emailCut it down to what the job needs
Vague purposeA description like “helps with stuff”Rewrite the description, or pass

One more: a skill that tells the bot to keep its instructions secret from you. A skill you can’t ask about is one you can’t trust. My own rule is that nothing in a skill is hidden from the person using it.

What each platform checks for you

Platforms add their own guardrails, and they help, but none of them replace reading the file.

  • Grok Bot: Auto Review checks each action before it runs, and shows an approval card when one needs your OK. You can add Ask first rules in Settings, such as “Ask first before sending any external email.” The docs also say text from an email or web page doesn’t count as your request.
  • ChatGPT: uploaded skills are scanned before they’re available. Some get marked Needs Review, and risky ones can be Blocked. OpenAI’s help page says the scan shouldn’t replace your own review.
  • Gemini CLI: per a compatibility survey of vendor docs, it shows a consent prompt naming the skill and the folder it will access before the skill activates.
  • Claude Code: its docs describe instruction files as context, not enforced settings. To block an action no matter what, they point to hooks.

Treat a skill’s approval rules as a second layer on top of these settings. If your platform can require approval before sending, posting, or paying, turn that on first. My guide on making your AI bot ask before it acts walks through both layers.

Checking a Grok Bot skill specifically

Grok Bot shares private skills across all your bots, so a skill you install for one bot can be used by the others. That makes the check more important, not less. Three extra things I look at:

  1. Does it name a bot or a team? Skills written for someone else’s setup may tell your bot to message people or channels that don’t exist for you.
  2. Does it set up routines? A skill that creates its own scheduled runs can spend usage while you’re away. The Grok Bot docs note that a busy routine can use a week of usage in a day.
  3. Does the install prompt fetch more than the skill? If a repo asks the bot to “follow the instructions in this repo,” ask the bot to show you the files first. My guide to installing Grok Bot skills from GitHub has a safer install prompt.

After you install it

  • Ask the bot to explain the skill’s rules back to you in its own words.
  • Watch the first few real runs. Check that it stops where it should.
  • Re-check when the skill updates. A changed file is a new skill.
  • Keep payment details out of bots you don’t fully trust. My guide on stopping your AI bot from spending money covers this.

FAQ

Can an agent skill contain malware?

Yes. A 2026 Snyk scan of 3,984 published skills confirmed 76 malicious payloads, and 13.4% of the skills had at least one critical-level issue. Read the file and every script before you install a skill.

Is it safe to install Grok Bot skills from GitHub?

It can be, if you read the SKILL.md and any scripts first, check for send and spend rules, and test it on something harmless. Grok Bot’s Auto Review and Ask first rules add a second layer, so keep them on.

Does a skill checker prove a skill is safe?

No. A checker matches patterns. It can miss problems and flag things that are fine. Use it to catch what you might skip, then make the call yourself.

What is the biggest red flag in a skill?

Instructions hidden from you, or wording that tells the bot to follow whatever it reads in emails or web pages. Either one is a reason not to install.
