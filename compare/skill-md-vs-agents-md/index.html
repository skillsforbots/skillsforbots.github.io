SKILL.md vs AGENTS.md vs CLAUDE.md: which file does what

All three are Markdown files of instructions for an AI agent, which is why people mix them up. The difference is when the agent reads them and what they’re for. Here’s the short version, then the details.

The short answer

  • SKILL.md teaches an agent one job. The agent sees only its name and description until a task matches, then loads the full file. It lives in its own folder and can bring scripts and reference files.
  • AGENTS.md tells coding agents how to work in one repository: setup commands, tests, code style. Agents read it as standing context for that project.
  • CLAUDE.md is Claude Code’s own instruction file, read at the start of every session. Claude Code can read AGENTS.md instead when a repo has no CLAUDE.md.

If you use a bot for everyday life rather than code, SKILL.md is usually the one you want. The other two are mostly for software projects.

SKILL.md: a job, loaded when needed

A skill is a folder with a SKILL.md file. The top has YAML frontmatter with two required fields. The spec says name is up to 64 characters of lowercase letters, numbers, and hyphens, matching the folder, and description is up to 1,024 characters saying what the skill does and when to use it.

The key idea is progressive disclosure. The agent loads every skill’s name and description at startup, which is small. It reads the full instructions only when it decides a skill fits, and reads extra files only when needed. That’s why you can install many skills without filling the agent’s memory.

Claude Code’s docs give a good rule of thumb: make a skill when you keep pasting the same instructions or checklist, or when a section of CLAUDE.md has grown into a procedure rather than a fact. My annotated SKILL.md template shows every part.

AGENTS.md: a README for coding agents

The AGENTS.md site describes it as “a README for agents”: a predictable place for the build steps, tests, and conventions a coding agent needs, kept out of the human README. It has no required fields. The site says it’s used by over 60,000 open-source projects and is now stewarded by the Agentic AI Foundation under the Linux Foundation.

Two rules from its FAQ are worth knowing. In a monorepo, the closest AGENTS.md to the file being edited wins. And your explicit chat prompts override everything in the file.

An AGENTS.md isn’t a skill. It doesn’t load on demand, it isn’t a reusable job, and it doesn’t travel from repo to repo. It’s the house rules for one codebase.

CLAUDE.md: Claude Code’s project memory

Claude Code reads CLAUDE.md files at the start of every session to carry instructions across chats. The docs list several places for them: a managed policy file for an organization, ~/.claude/CLAUDE.md for your own preferences across projects, ./CLAUDE.md or ./.claude/CLAUDE.md for a project, and CLAUDE.local.md for personal project notes you keep out of version control.

On AGENTS.md, the docs say Claude Code reads it when the repo has no CLAUDE.md, reads only CLAUDE.md when both exist, and can include AGENTS.md through an import. They also note that these files are treated as context, not enforced configuration.

Which one should I write?

  • You want a bot to do a job your way, in any tool: write a SKILL.md.
  • You want coding agents to follow a repo’s setup and style: write an AGENTS.md.
  • You only use Claude Code and want always-on project notes: write a CLAUDE.md, or reuse your AGENTS.md through an import.
  • You run a personal assistant like Grok Bot: skills for each job, plus short standing instructions in the bot’s profile for the rules that apply to everything, such as approval rules.

Using them together

In a code project, a common setup is an AGENTS.md for the always-true facts (how to run tests, which folders matter), a CLAUDE.md that imports it if anyone uses Claude Code, and skills for repeatable procedures like releasing a version or writing a changelog. Keep each fact in one place. If the same rule appears in two files, they will drift apart.

Safety rules are the exception I repeat on purpose. I put no-send and no-spend rules in the always-loaded file and in each skill that could send or spend, because a skill may run in a tool that never reads the other file.

Moving instructions from one to another

  1. Find sections of your CLAUDE.md or AGENTS.md that read like a procedure: numbered steps, a checklist, an output format.
  2. Move each one into its own skill folder with a clear name and a description that says when to use it.
  3. Leave one line behind, such as “For releases, use the release skill.”
  4. Check the new file with my SKILL.md checker, then test that the agent picks it up.

Cursor has a built-in /migrate-to-skills skill that converts some rules and slash commands into skills, per its docs.

FAQ

Is AGENTS.md the same as SKILL.md?

No. AGENTS.md holds standing instructions for coding agents working in one repository. SKILL.md teaches an agent one job and loads only when a task matches it.

Does Claude Code read AGENTS.md?

Yes. Its docs say Claude Code reads AGENTS.md when a repo has no CLAUDE.md, reads only CLAUDE.md when both exist, and can include AGENTS.md through an import.

Do I need all three files?

No. For everyday bot use, skills are usually enough. AGENTS.md and CLAUDE.md are mainly for software projects.

Which file has required fields?

Only SKILL.md. It needs a name and a description in YAML frontmatter. AGENTS.md and CLAUDE.md are plain Markdown with no required fields.
