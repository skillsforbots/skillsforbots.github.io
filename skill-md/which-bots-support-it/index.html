The short answer

Most major AI coding and assistant tools now read the Agent Skills format: a folder with a SKILL.md that starts with a name and description. Anthropic created it, made it an open standard, and in October 2026 handed it to the Agentic AI Foundation under the Linux Foundation, saying more than 70 agent platforms had built it in.

What differs is the folder each tool reads, the extra header fields it understands, and how you switch a skill on. The table below covers those differences.

The one folder most tools share

The vendor-neutral .agents/skills/ folder (and ~/.agents/skills/ in your home folder) is the closest thing to a universal location. The Skills Board survey found that 8 of 11 tools with documented support scan it. Since then I’ve confirmed Codex and Cursor read it, and OpenClaw’s docs list it too.

The big exception is Claude Code, which lists only .claude/skills/ and ~/.claude/skills/. If you use Claude Code with other tools, keep the skill in .agents/skills/ and symlink it into .claude/skills/. Claude Code’s docs say symlinked skill folders work.

App-based tools have no folder at all. In the Claude apps you upload a ZIP. In ChatGPT you create or upload in the Skills tab. In Grok Bot you ask the bot to save the skill to your private library. See my install hub for the steps in each.

What travels between tools, and what doesn’t

Part of a skillPortable?
name and descriptionYes. Every documented tool reads both
Plain Markdown instructionsYes
references/ and assets/ filesMostly, where the tool supports extra files
scripts/Only where the tool can run code, and the right language is installed
Extra header fields like paths, disable-model-invocation, allowed-toolsTool-specific. Others may ignore them, and some packaging paths reject unknown fields
How it’s switched on and invokedNo. /name, $name, @name, or asking by name, depending on the tool

No conformance test exists. The survey points out that no tool claims a spec version, and nobody publishes results showing a skill behaves the same in two products. So “works in” means “reads the file,” not “behaves identically.” Test in each tool you rely on.

How to write one skill for many bots

  1. Use only name and description in the header. The spec allows license, compatibility, and metadata too, which are harmless.
  2. Keep name lowercase with hyphens, up to 64 characters, matching the folder.
  3. Keep description under 1,024 characters, and put the trigger words first. Some tools shorten descriptions when many skills are installed.
  4. Write the body as plain steps and rules. Avoid tool names in the steps unless the skill is meant for one tool.
  5. Put “ask before acting” rules in the skill itself, since each tool’s settings differ. My approval rules template is ready to paste.
  6. Check it with my SKILL.md checker, then test in each tool.

My SKILL.md template follows these rules, and so do my free skills on GitHub, such as the Bot Safety Rules Starter.

How I checked this

For the rows marked as read today, I opened each vendor’s current skills documentation and copied only the folders it names. For the others, I relied on the Skills Board survey, which applies a strict bar: the vendor’s own docs must say the product reads SKILL.md. If you spot a change, the vendor’s page is the source of truth.

FAQ

Which AI tools support SKILL.md?

Tools whose own docs describe reading SKILL.md include Claude Code, the Claude apps, ChatGPT, Codex, Cursor, GitHub Copilot, VS Code, Gemini CLI, OpenCode, goose, Amp, and OpenClaw. Grok Bot supports skills in a private library, and community repos install SKILL.md folders into it.

Where should I put a SKILL.md so the most tools find it?

In .agents/skills//SKILL.md in a project, or ~/.agents/skills//SKILL.md in your home folder. Claude Code is the main exception and reads .claude/skills/ instead.

Will one skill behave the same in every tool?

Not guaranteed. The name, description, and plain instructions travel well, but there’s no conformance test, and extra header fields and invocation differ. Test in each tool you rely on.

Does Grok Bot read SKILL.md files?

The Grok Bot docs describe skills as reusable instructions saved to a private library, without naming the file format. Community repos install SKILL.md folders into it, and my own skills are written in that format and tested in Grok Bot first.
