Grok Bot skills vs routines: the how and the when

A skill is the method. A routine is the alarm clock. Most beginner confusion comes from expecting one to do the other’s job. Here’s how they fit together, with two setups I use.

The difference in one line

A skill is saved instructions for how to do a task. A routine tells a bot when to start, either at a time or when something happens. The Grok Bot docs put it this way: a skill describes how to perform a task, and a routine assigns a workflow to one bot and tells it when to run.

You often need both. A routine without a skill runs a vague one-line prompt every morning. A skill without a routine waits until you remember to ask.

How Grok Bot handles each

  • Skills: private skills are one library shared by all your Bots. A Bot may still need the right app or login to use one. If a Bot can’t find a skill, enable it for that Bot under Private skills in Connect apps.
  • Routines: a routine belongs to one Bot. It can run on a schedule or start from an event, such as a Slack message, a GitHub, Linear, Sentry, or PagerDuty event, an email to the Bot’s own address, or a webhook call. Routines run in the cloud while your laptop is closed.
  • Limits: a Bot can own up to 50 routines, and schedules must be at least five minutes apart. The docs list a limit of 300 runs an hour across all your routines and 200 an hour for any one routine, and the app keeps the 20 most recent run records for each routine.

Because one skill serves every Bot, keep the logic in the skill and the routine instruction short. Several Bots can then run the same skill on their own schedules.

How to pair a skill with a routine

This is the order the Grok Bot docs recommend, and it’s the order I use.

  1. Do the task once, by hand, in chat. Get one good result first. Fix the steps until the output is what you want.
  2. Save the method as a skill. Write the steps, the rules, the output format, and what needs your approval. Give it a clear name and description.
  3. Create the routine. Ask the bot to run that skill on a schedule, in your time zone, with a clear result and what to do if a source is missing.
  4. Test it before you trust it. Run the routine once with a safe input, then check the first scheduled run.
  5. Review the usage. Each run spends usage. Widen the schedule or narrow the trigger if it runs more than it needs to.

A routine instruction can then be one or two lines:

Every weekday at 8:00 AM, use the morning-brief skill.
Post the result in this chat. Don't send anything to anyone else.

In Grok Bot, a new routine waits for its next scheduled time rather than running when you create it. Use Test to run it now. A test run does real work, so keep write actions behind approval.

Example 1: a reminder that nags until done

The problem: a one-time reminder fires, you swipe it away, and the task never happens.

The skill holds the rule that matters: the reminder comes back on every run until you clearly say it’s done. “Thanks,” “ok,” and “later” keep it open. My free Reminder Basics skill does exactly this for one item.

The routine just says when: “Every day at 9:00 AM, use reminder-basics.” Without the skill, the routine would remind you once and consider the job finished. Without the routine, the skill would only remind you when you asked, which defeats the point.

For a whole list on one reminder, with weekly or monthly schedules, the Nag-Until-Cleared Reminders pack ($9) adds commands to add, clear, pause, or show items. My guide on reminders that don’t stop until you’re done covers the setup.

Example 2: a sprint before a usage reset

The problem: your plan’s usage resets on a set day, and whatever is left over is wasted.

The skill checks how much usage is left and when it resets, picks a chunk of a project that fits, saves progress as it goes, and leaves a handoff note. It never buys more usage. My free Usage Reset Sprint does one window.

The routine starts it a few hours before the reset. If your reset time moves, change the routine, not the skill. For projects that span several resets, the Project Sprint pack ($19) plans the windows ahead. The guide on using remaining usage before a reset explains the steps.

Common mistakes

  • Putting the whole method in the routine. Long routine prompts are hard to edit and can’t be reused by your other Bots. Move the steps into a skill.
  • Broad triggers. A trigger on every message in a busy channel runs often. The Grok Bot docs warn that an hourly schedule or a busy Slack trigger can use a week of usage in a day.
  • No missing-data rule. Tell the bot what to do when a source is down. “Report the failure, don’t use old data” is a good default.
  • Skipping approval rules. Routines run while you’re away, so the skill should say what needs your yes. See my approval rules template.
  • Wrong time zone. In Grok Bot, schedules use the time zone under Settings, Bot, Timezone. Open the routine and check “When to run” after you create it.

FAQ

What is the difference between a skill and a routine?

A skill is saved instructions for how to do a task. A routine tells one bot when to start it, at a time or when an event happens.

Do I need a skill to use a routine?

No, but it helps. A routine can run a short prompt on its own. Putting the method in a skill keeps the routine short, makes the steps reusable, and lets your other Bots use the same instructions.

Do routines use up my usage?

Yes. Each run spends usage, even when nothing changes. Widen schedules and narrow triggers for routines that don’t need to run often.

Can one skill run on routines for different Bots?

Yes. Private skills are one library shared by all your Bots, while each routine belongs to one Bot. Keep the logic in the skill and give each Bot its own short routine.
